# 補強計畫書

建立日期：2026-10-12。依序施作；每一項都要有驗收條件，通過測試才算完成。狀態會隨進度更新。

## 背景
使用者回報一個問題，並要求針對對手比較後找出的弱點補強：

1. **Bug**：3D／動畫擷取時，十個分頁都有動畫卻只擷取一個（重現：預設只爬 6 頁、動畫只擷取 5 頁）。
2. 單項深度不如專門工具（技術辨識、效能、TLS、HTML 驗證）。
3. 設計擷取輸給 dembrandt／tokenscout（深色模式 token、品牌手冊、對照 token 檔、色彩分群、隱身模式）。
4. 新手門檻高（選項太多）。
5. 平台與驗證不足（Windows 完整流程未通過；沒有真實網站測試）。
6. 沒有偏移歷史介面。
7. 最後：調整介面（UI／UX）。

## 施作順序與驗收

## 不在範圍內
- 託管雲端服務與帳號系統（需要伺服器與維運，不是這個工具的方向）。
- 完整追平 Lighthouse、Wappalyzer、SSL Labs：只補上最有感的幾項。
- 判斷網站是否由 AI 生成、弱點掃描。

## 每一項的完成流程
實作 → 測試 → 全套測試 → 開 PR → CI 通過後合併 → 更新本表與 `docs/COMPARISON.md`、`docs/TEST-REPORT.md`。
